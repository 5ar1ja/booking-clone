# План работы и распределение задач (Booking Clone)

## Команда (4 человека)

### 1. Team Lead / DevOps (Студент 1)
**Роль:** Управление проектом, инфраструктура, архитектура и релиз-менеджмент.
**Задачи:**
- [ ] **GitHub Workflow:** Настроить защиту ветки `main` (запрет прямого push). Внедрить обязательное Code Review через Pull Requests.
  - [ ] Создать репозиторий (если еще не создан) и пригласить команду.
  - [ ] Включить Branch Protection Rules в GitHub для `main`.
  - [ ] Настроить шаблон для Pull Request (PR template).
- [ ] **Docker & Nginx:** Настроить `docker-compose.yml` (Django, PostgreSQL, Redis, Celery). **Устранить прошлые баги:**
  - [ ] Написать/обновить `Dockerfile` для Django и Celery.
  - [ ] Написать `docker-compose.yml` с сервисами: `web`, `db`, `redis`, `celery`, `nginx`.
  - [ ] Обновить `default.conf` для Nginx: маппинг статики (`/static/`) и медиа (`/media/`).
  - [ ] Закрыть порт `8000` извне (убрать `ports: "8000:8000"` у сервиса `web` в docker-compose).
- [ ] **Конфигурация (Settings):** Разделить настройки.
  - [ ] Создать `settings/base.py`, `settings/local.py`, `settings/prod.py`.
  - [ ] Заменить все хардкод-адреса (`127.0.0.1`) на вызовы из `.env`.
  - [ ] Настроить парсинг `.env` файла (через `python-dotenv` или `environ`).
  - [ ] Добавить `.env.example` в репозиторий.
  - [ ] Внедрить "Fail-fast" (выбрасывать исключение `ImproperlyConfigured`, если переменная окружения отсутствует).
- [ ] **Логирование:**
  - [ ] Прописать настройки логирования (`LOGGING`) в `settings/base.py`.
  - [ ] Настроить ротацию лог-файлов.
  - [ ] Добавить логирование важных событий (авторизация, ошибки) в код.
- [ ] **Менеджмент:**
  - [ ] Создать проект в Actarum.
  - [ ] Завести эпики и таски согласно этому плану.
  - [ ] Проводить Code Review (ревьюить PR от команды).

### 2. Backend Developer / Auth & Models (Студент 2)
**Роль:** Проектирование базы данных, авторизация, локализация.
**Задачи:**
- [ ] **Архитектура БД (ER-диаграмма):**
  - [ ] Нарисовать ER-диаграмму и согласовать с командой.
  - [ ] Создать модели для приложения `properties` (Дома, Удобства, Правила).
  - [ ] Создать модели для приложения `bookings` (Бронь, Статусы, Оплата).
  - [ ] Создать модели для приложения `reviews` (Отзывы, Рейтинги).
- [ ] **Custom User & Роли:**
  - [ ] Создать кастомную модель пользователя, наследуемую от `AbstractUser`.
  - [ ] Реализовать логику ролей (`is_rentor`, `is_landlord`) с использованием исключающего ИЛИ (XOR) (например, свойство (property) валидации или переопределение метода `save`).
- [ ] **Auth:**
  - [ ] Установить и настроить `djangorestframework-simplejwt`.
  - [ ] Создать эндпоинты для регистрации, логина и рефреша токена.
- [ ] **Clean Code:**
  - [ ] Вынести статусы бронирований, роли и прочие константы в `choices` внутри классов моделей.
  - [ ] Проверить весь код на предмет магических чисел и вынести их в константы.
  - [ ] Очистить код от неиспользуемых импортов.
- [ ] **Локализация (i18n):**
  - [ ] Настроить `USE_I18N = True`, подключить middleware.
  - [ ] Добавить переводы (`ugettext_lazy` / `gettext_lazy`) для полей моделей и сообщений об ошибках.
  - [ ] Сгенерировать и перевести файлы `.po` (`makemessages` и `compilemessages`).

### 3. Backend Developer / API & Optimization (Студент 3)
**Роль:** Разработка бизнес-логики, сериализаторов, оптимизация запросов и асинхронность.
**Задачи:**
- [ ] **Сериализаторы:**
  - [ ] Написать `CreateSerializer` и `ListSerializer`/`RetrieveSerializer` для `properties`, `bookings`, `reviews`.
  - [ ] Убедиться, что дублирующийся код сериализаторов вынесен в миксины.
  - [ ] Добавить поле `id` во все отдающие сериализаторы (для фронтенда).
- [ ] **ViewSets & Views:**

  - [ ] Настроить `APIView` для сложной логики (например, подтверждение брони).
  - [ ] Написать подробные Docstrings для каждого метода (что принимает, что возвращает).
- [ ] **Оптимизация API:**
  - [ ] Интегрировать `django-filter` для фильтрации GET-запросов (поиск по цене, городу и т.д.).
  - [ ] Использовать `select_related` для внешних ключей (Foreign Key) в `get_queryset`.
  - [ ] Использовать `prefetch_related` для отношений многие-ко-многим (M2M).
  - [ ] Добавить агрегацию (например, подсчет среднего рейтинга через `annotate`).

  - [ ] Установить и настроить `drf-yasg` или `drf-spectacular` (Swagger/Redoc).
  - [ ] Указать относительные пути для Swagger UI.
  - [ ] Описать примеры запросов и ответов.
- [ ] **Асинхронность:**
  - [ ] Настроить ASGI (`asgi.py`).

## 🛑 Анализ прошлых ошибок и что нужно исправить в первую очередь:

1. **Конфигурация окружения (`settings` и `.env`):**
   * *Проблема в прошлом:* Терялись файлы настроек из-за некорректного `.gitignore`, неправильно выставлялись `ALLOWED_HOSTS` для local/prod.
   * *Решение:* Строго отслеживать `.env.example` (добавить его в репозиторий), разделить настройки на модули, убедиться что `DEBUG` правильно переключается.
2. **Nginx и Docker:**
   * *Проблема в прошлом:* Сложности с маппингом статики, "торчащие" порты.
   * *Решение:* Nginx должен быть единственной точкой входа (порт 80/443). Сервис `web` (Django) должен общаться с Nginx только по внутренней Docker-сети (без `ports: "8000:8000"`).
3. **Hardcoded адреса:**
   * *Проблема в прошлом:* `127.0.0.1` прописан прямо в коде.
   * *Решение:* Заменить все локальные пути на переменные окружения (или относительные пути для Swagger).
4. **Безопасность ветки `main`:**
   * *Проблема в прошлом:* Пуши в `main` напрямую.
   * *Решение:* Настроить branch protection rules в GitHub.
5. **Логика моделей (Rentor/Landlord):**
   * *Проблема в прошлом:* Некорректное наследование или смешивание ролей.
   * *Решение:* Использовать XOR при проверке/установке ролей арендатора и арендодателя.
